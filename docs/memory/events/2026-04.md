## MEM-2026-04-25-002

- Date: 2026-04-25
- Scope: Reviewed GitHub issue #8 about short noisy scanner audio running to
  `max_new_tokens` when EOS is never emitted.
- Decision:
  - Treat the issue as valid and connected to the v0.3.2 long-audio fix: the
    current 30s chunking prevents long-form truncation, but the 4096-token
    per-chunk default creates a large worst-case decode stall for short
    low-information audio when EOS/repetition stops do not trigger.
- Reuse next time:
  - Separate long-audio chunking from per-chunk decode caps. Prefer adaptive
    per-chunk token budgets plus explicit max-budget/timeout metadata over a
    single large static default.
- Evidence:
  - GitHub issue #8
  - `mlx_qwen3_asr/generate.py`
  - `mlx_qwen3_asr/transcribe.py`
  - `mlx_qwen3_asr/session.py`
  - `mlx_qwen3_asr/chunking.py`
  - Commit `5b6af13`
