# Implementation Memory - 2026-11

## MEM-2026-11-17-001

- Date: 2026-11-17
- Scope: Greedy decode pipelining in `generate_with_info` (external PR).
- Decision: For temperature 0, queue the step for token i+1 with
  `mx.async_eval` before reading token i on the host (as mlx-lm's
  `generate_step`). Sampled and speculative decoding are unchanged; stopping
  rules (EOS, repetition, budget) are the same, and one extra step is computed
  after the last token and discarded.
- Reuse next time:
  - A per-token `.item()` before building the next step leaves the GPU idle
    for every host round trip; overlap it whenever the next input can stay on
    the device (here `argmax` feeds `model.step` directly).
  - `test_blockwise_encoding_matches_full_pass_up_to_rounding` is flaky on
    MLX 0.32.4 on an M5 Ultra (fails 2 of 3 runs on `main` too); it is not a
    signal for decoder changes.
- Evidence: Qwen3-ASR-1.7B FP16 on an M5 Ultra, 100 LibriSpeech test-clean
  files, model loaded and warmed once, two interleaved runs per arm:
  `main` 16.77 / 16.47 s, this change 14.85 / 14.85 s (1.12x); all 100
  transcripts identical to `main`; peak MLX memory unchanged (8.16 GB).
