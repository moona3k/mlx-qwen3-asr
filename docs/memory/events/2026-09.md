# Implementation Memory - 2026-09

## MEM-2026-09-06-001

- Date: 2026-09-06
- Scope: Issue #16 / PR #18. Server inference failed on MLX 0.31+ with
  `There is no Stream(gpu, 1) in current thread`.
- Decision:
  - Root cause is library-level, not server-level: init-time buffers that are
    not parameters (`SinusoidalPositionEmbedding._pe`,
    `InterleavedMRoPE._inv_freq`) were lazy graphs bound to the constructing
    thread. Materialize them with `mx.eval` in `__init__`.
  - Keep PR #18's dedicated single-worker executor in the server as defence in
    depth, with `try/finally` cleanup and `shutdown(wait=True)` off the loop.
- Reuse next time:
  - Bisect thread-affinity failures op by op on a worker thread; `nn.Linear`
    weights and `mx.load` tensors are portable, only unevaluated graphs are
    not. `mx.eval(model.parameters())` does not reach underscore attributes.
  - Build test inputs inside the worker thread; otherwise `mx.zeros` created
    on the test thread reproduces the bug for the wrong reason.
  - Keep a second venv with the newest MLX; the repo venv (0.30.6) hides
    every thread-affinity bug and the newer `as_strided` error.
- What did not work:
  - `mx.synchronize()` or `mx.set_default_stream(...)` on the worker thread.
  - Evaluating `model.parameters()` alone.
- Evidence:
  - Probe matrix on MLX 0.32.2: load main/infer worker FAIL; load worker A /
    infer worker B FAIL; load+infer same thread OK; after buffer eval all OK.
  - `tests/test_model.py::TestThreadPortability` fails on MLX 0.32.2 without
    the fix and passes with it; passes on 0.30.6 either way.
  - `mlx_qwen3_asr/encoder.py`, `mlx_qwen3_asr/mrope.py`,
    `mlx_qwen3_asr/server.py`

## MEM-2026-09-06-002

- Date: 2026-09-06
- Scope: Issue #15. Chinese SRT cues cut every 10 characters.
- Decision:
  - The forced aligner drops punctuation for every language and emits one
    segment per CJK character, so `max_words=10` cut phrases. Subtitle grouping
    now restores transcript punctuation onto segments (grouping only, the
    `segments` contract is unchanged), measures width in display cells, applies
    the word cap only to space-delimited languages, and prefers clause and
    sentence boundaries.
- Reuse next time:
  - Reproduce subtitle issues with `say -v Meijia` (macOS Mandarin voice) piped
    through ffmpeg to 16 kHz WAV; the aligner needs
    `Qwen/Qwen3-ForcedAligner-0.6B` cached.
  - Building regexes from f-strings with `]` inside a character class silently
    breaks; use `re.escape` for the closer set.
- Evidence:
  - Before: `大家好今天我们继续学` / `习真实义品上一次我们`.
    After: `大家好，今天我们继续学习真实义品。` / `上一次我们讲到三曲空这一段，`.
  - `mlx_qwen3_asr/writers.py`, `tests/test_writers.py`

## MEM-2026-09-11-008

- Date: 2026-09-11
- Scope: Quantized 1.7B checkpoints promoted float16 inference to float32.
- Decision:
  - Treat the public `dtype` argument as the activation-dtype contract for
    quantized and unquantized models alike. After loading, cast every floating
    parameter leaf to the requested non-float32 dtype; integer-packed
    quantized weights remain untouched.
- Reuse next time:
  - A quantized checkpoint still has floating scales, biases, norms, and
    unquantized layers. If their dtype differs from the input dtype, check
    `mx.result_type` before blaming individual encoder or decoder operations.
- Evidence:
  - On MLX 0.32.2, both cached `mlx-community/Qwen3-ASR-1.7B-{4bit,8bit}`
    models changed from 906 bfloat16 floating tensors and float32
    encoder/logit/KV outputs to 906 float16 floating tensors and float16
    outputs; all 198 packed weights stayed uint32.
  - Warm fixture and repeated 10 s hypotheses were unchanged. Mean latency
    improved 19.8-32.3%; peak MLX allocation fell 0.718-0.756 GiB.
  - `tests/test_load_models.py::TestLoadModelWithCommunityLayouts::test_quantized_bfloat16_checkpoint_uses_requested_activation_dtype`
    fails before the loader fix and passes after it; fast gate passes with
    665 tests and 2 skips.

## MEM-2026-09-19-009

- Date: 2026-09-19
- Scope: Review and land external PRs #20 (quantized dtype cast) and #21
  (encoder tail-chunk padding).
- Decision:
  - Merge both. #21 is a real parity fix: the official `qwen_asr` encoder
    `pad_sequence`s a sample's chunks before the conv stem and masks post-CNN
    tokens, so a tail after a full chunk is convolved at width 100. The MLX
    path convolved it at its own width; with non-zero conv biases the last
    valid tail token differed (max abs 0.0068 on the fixture, 0.6B fp16).
  - Rewrite the PR's Chinese comments in English; document tail padding in
    `docs/ARCHITECTURE.md`; include dtype in the quantized-load log line.
- Reuse next time:
  - `transformers`' `Qwen3ASREncoder` always pads to a multiple of 100
    (feature extractor pads the mel axis), so sub-chunk inputs differ between
    `transformers` and `qwen_asr`. The parity lane uses `qwen_asr`; follow it.
  - When running repo scripts from a worktree with the repo `.venv`, the
    editable install resolves `mlx_qwen3_asr` to the main checkout. Set
    `PYTHONPATH=<worktree>` (only `python -m pytest`/`python -c` use cwd) and
    print `mlx_qwen3_asr.__file__` before trusting any before/after numbers.
- Evidence:
  - Independent check of #20 on `mlx-community/Qwen3-ASR-0.6B-4bit`, MLX
    0.32.2: floating params bfloat16 -> float16, same transcript, warm
    latency 0.226 s -> 0.154 s, peak 1.99 -> 1.47 GiB.
  - `scripts/eval_librispeech.py --samples 100 --sampling speaker_round_robin`
    before and after both merges: WER 2.331% / CER 0.587% unchanged, 0/100
    hypotheses changed.
  - Fast gate: 673 passed, 2 skipped on MLX 0.30.6; suite green on 0.32.2.
